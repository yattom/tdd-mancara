# tdd-mancara

TDD の練習セッションのリポジトリ。

## 演習の目的と概要

- お題は別の Claude セッションが提示する。仕様は段階的に提示され、仕様の変更に合わせて TDD で設計を変えていく。
- Claude Code の能力を積極的に利用する。ただしすべて任せるわけではなく、人間が必要に応じて判断を加えながら、技術的負債や認知負債を少なく維持する。
- 言語などの環境がまったくない状態から開始する。
- 経過を細かく Git にコミットしながら進める。コミットは人間がしても、Claude Code がしてもよい。
- TDD は Kent Beck が定義する Canon TDD に従い、Red/Green TDD を実践する。
- 自動テストについては、TDD で作るテストに限定せず、効果的に使えるテスティングの戦略やプラクティスを積極的に導入、利用する。
- 意志決定の履歴や結論をドキュメントに残していく。
- 時間は 2 時間（ポモドーロタイマー 4 周）で一区切りとする。
- t-wada さんによる TDDBC 仙台での実践を参考にする。直接真似するわけではないが、アイデアを借りることはある。お題は違うもの。
  - https://t-wada.hatenablog.jp/entry/red-green-tdd-with-claude-code-202610

## お題：環のマンカラ

### 前提・共通ルール

- 小さなテストから始めて段階的に作り込む、TDDの演習です。各STEPで公開された仕様だけを対象に、Red → Green → Refactor で実装します。
- お題に書かれていないマンカラのルールは、存在しないものとして扱います。自分の陣地、ストア、相手側の穴などはありません。先のSTEPを想定した作り込みも不要です。
- 入力の扱いやエラーの表現など、決まっていないことは自分（ペア）で決め、その決定をテストとして残します。
- 1人で指します。

### 用語

- 穴（pit）：輪の形に並んだ8つのくぼみです。番号は1〜8で、8の隣は1です。
- 石（stone）：穴に入っている小石です。
- 盤面（board）：穴1〜8それぞれに入っている石の数です。[穴1, 穴2, …, 穴8] の順に書きます。
- 初期盤面：すべての穴に石が3個ずつ入った状態、[3,3,3,3,3,3,3,3] です。
- 手（move）：穴を1つ選び、その穴の石を蒔くことです。
- 蒔く（sow）：取り出した石を、隣の穴から1個ずつ順に置いていくことです。
- 時計回り：番号が増える向きです（…→7→8→1→2→…）。

### STEP 01：1手を指す

#### 01-1

初期盤面から1手を指したあとの盤面を求めます。選んだ穴の石をすべて取り出し、時計回りに隣の穴から1個ずつ置きます。

- 穴2を選ぶ → [3,0,4,4,4,3,3,3]
- 穴8を選ぶ → [4,4,4,3,3,3,3,0]（8の次は1です）

#### 01-2

存在しない穴は選べません。

- 穴0、穴9は選べない

STEP 01ができたら声をかけてください。次のステップをお出しします。
