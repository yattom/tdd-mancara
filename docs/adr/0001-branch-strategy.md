# 0001 ブランチ戦略

- 日時：2026-11-13 12:58

## 決めたこと

- GitHub は使わず、ローカルの Git だけで進める。PR は作らない。
- main は作業セッションが終わるまで触らない。
- セッション中は develop をトランクとして扱う。
- 作業内容に応じて develop からフィーチャーブランチを切り、区切りがついたら `git merge --no-ff` で develop にマージする。

## 背景と理由

- main に直接コミットするのは避けたい。
- フィーチャーブランチの単位を STEP にすると大きすぎるので、作業内容に応じて決める。
- `--no-ff` でマージコミットを残すと、細かい Red/Green のコミットと、作業のまとまりの両方を履歴から追える。

## 検討した他の案

- **develop を1本切り、ずっとそこにコミットする**：単純だが、作業のまとまりが履歴から読み取れない。
- **t-wada さんの TDDBC 仙台での進め方**：作業ごとにブランチを切り、PR を積み重ねていた（Stacked PR）。今回は GitHub を使わないので、PR の部分は採用しない。
- **早送りマージ**：履歴は一直線になるが、作業の区切りが消える。
